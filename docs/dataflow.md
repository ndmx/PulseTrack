# PulseTrack civic data flow

_Updated: 2026-10-23_

## Current views

- `/insights` reads `state_demographics` from Firestore and displays voter and population records by state.
- The community estimates on `/insights` come from `frontend/public/snapstats/derived/tribe_stats.json` (or the configured Snapstats URL). They describe the existing dataset, not voter preferences or predictions.
- `/snapstats` reads static GeoJSON and derived demographic files for its map and geographic explorer.
- The PulseTrackr safety home uses the separate shared safety collections and functions documented in `docs/web-unification.md`.

## Retired candidate opinion flow

- The previous browser opinion form is no longer rendered.
- `/api/submit_opinion` and `/api/admin_upload` remain deployed as HTTP 410 responses for cached clients and old integrations. They do not write `raw_inputs`.
- The scheduled `process_etl` function is removed; no new `sentiment_breakdown` or `approval_ratings` records are generated by this pipeline.
- Existing `raw_inputs`, `sentiment_breakdown`, `approval_ratings`, and rollup documents remain in Firestore. This change does not delete historical records.
- `functions/etl_processor.py`, older frontend sentiment components, and `seed.js` remain in the repository as historical code, and must not be used as active collection paths.

## Data quality

The voter and community datasets have no current provenance or update date in the app. The interface labels them as existing records and estimates. Verify their original source and methodology before relying on them for election decisions.
